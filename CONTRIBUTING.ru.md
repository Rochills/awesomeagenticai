# Contributing

> [繁體中文](./CONTRIBUTING.md) | [English](./CONTRIBUTING.en.md) | **Русский**


Спасибо, что задумался над контрибьютом. **Это курируемая карта обучения, не исчерпывающий каталог. Качество > количество.**

Этот репо **спроектирован для community-driven улучшений** — один человек не успевает за экосистемой AI agents в одиночку. Ежеквартального ревью мейнтейнера недостаточно; нужно больше глаз.

Каталог разбит на **две дорожки**: **Track A** (CLI Power User, `tracks/cli/A1-A3`) и **Track B** (Agent Builder, `stages/03-07`). При контрибьюте укажи, какой track модифицируешь — у двух разная аудитория.

## 🚪 Первый раз контрибьютишь: 5 простых точек старта

Не уверен, с чего начать? Выбери одно, что закончишь за 30 минут:

1. **🐛 Сообщи о stale-записи**: запусти `python scripts/refresh-stars.py`, найди репо со значительным star-сдвигом, открой issue «это надо убрать / обновить»
2. **🔗 Почини одну битую ссылку**: попал на 404 при чтении этапа X? Просто PR с фиксом
3. **✍️ Заполни секцию «Run it» в записи**: у многих записей нет install-команд; если запускал — добавь
4. **🌏 Улучши одну фразу английского companion**: возьми любой `.en.md`, сравни с zh-версией, поправь одну неуклюжую формулировку
5. **💬 Добавь личную заметку к записи**: застрял на `Упражнении 3`? Добавь строку «Note: xxx»

Никакое из этих не требует читать полный style-guide; они мержатся быстро — идеально для первого PR.

> 🧪 **Запускаешь walkthrough / build-скрипт / CI workflow впервые?** См. [`.github/TESTING-STATUS.md`](.github/TESTING-STATUS.md) — **честное раскрытие** того, что мейнтейнер реально исполнил vs только syntax-check vs совсем не тестировал. Быть первым, кто поймает баг и откроет issue + PR — самая ценная контрибьюция.

## Что принимаем

### Высокоценные PR
- **Добавление проекта** в этап с обоснованием, почему он учит этому этапу
- **Перевод** страницы этапа на 繁中 (только Traditional Chinese — мы НЕ zh-Hans) или другие языки
- **Флагирование stale / неподдерживаемых проектов** (открой issue сначала)
- **Улучшение curation-заметок** существующих проектов (более чёткие «what it teaches» объяснения)
- **Реорганизация** внутри этапа, если текущий порядок не соответствует learning progression

### Меньший приоритет (всё равно welcome)
- Фиксы опечаток
- Фиксы ссылок (проверь сначала `curl -I`)
- Полировка описаний этапов

### Не принимаем
- Bulk-добавление репо без curation-обоснования
- Self-promotion без educational ценности
- Проекты без документации
- Проекты без чёткой лицензии

## Как добавить проект

Каждый проект в странице этапа должен следовать формату:

```markdown
### [Project Name](url)

| Field | Value |
|---|---|
| Language | Python / TS / etc. |
| Stars | ★ k |
| License | MIT / Apache 2 / ... |
| Recommendation | ⭐⭐⭐⭐ |

**What it teaches**: 1-предложение core learning.

**Best for**: кому стоит изучать и почему.

**Notes**: 1–3 предложения личной оценки. Что сильно, что слабо, что пропустить.

**Run it**:
\`\`\`bash
# минимальная install / first-run команда
\`\`\`
```

## Curation-критерии

Проект, заслуживающий списка, должен иметь:

1. **Активную поддержку**: коммиты за последние 6 месяцев ИЛИ явная «stable, no longer maintained» заметка
2. **Документированный hello-world**: читатель должен суметь что-то запустить за 30 минут
3. **Чёткую лицензию**: MIT, Apache 2, BSD или сравнимое. Избегай no-license репо.
4. **Заслуживающий доверия мейнтейнер**: well-known org, компания или индивид с track record'ом

## Multilingual-стиль

- **Traditional Chinese (zh-TW) — каноничный**; English (`*.en.md`), zh-Hans (`*.zh-Hans.md`), Русский (`*.ru.md`) — companion'ы.
- **zh-Hans PR не принимаются как канонические**. Если шлёшь zh-Hans в как canonical — попросим конвертнуть.
- **Естественный перевод**, не слово-в-слово. Технические термины могут оставаться на английском, где естественно («使用 LangGraph 建 multi-agent 系統» / «MCP-сервер для tool use»).
- **Полные style-правила: см. [`resources/style-guide.md`](resources/style-guide.md)** (zh) или [`resources/style-guide.en.md`](resources/style-guide.en.md) (en) или [`resources/style-guide.ru.md`](resources/style-guide.ru.md) (ru) — banned words, схема записи, license-конвенции, writing-стиль, определения recommendation star — всё там. Читай перед PR.

## Процесс

1. Открой issue сначала для новых проектов или бóльшей реструктуризации
2. PR со сфокусированным scope (один этап за раз)
3. Жди review (обычно 7 дней)
4. Ревьюер может попросить уточнить «почему это учит этому этапу»

## Анти-паттерны для избегания

- ❌ «leverage», «delve», «comprehensive», «robust» (LLM-маркеры)
- ❌ Hype-рамка («revolutionary», «game-changing»)
- ❌ Списывание проекта только потому, что он популярен
- ❌ Длинные цитаты из собственного marketing-текста проекта

## Стать мейнтейнером этапа / ветки

Помимо one-shot PR, приветствуются **long-term мейнтейнеры** конкретных этапов
или веток — ответственные за периодическое ревью, triaging issues в этой области
и гейтинг PR.

Процесс self-nomination'а:
1. Открой issue с заголовком `[maintainer] Stage N — your-handle` или `[maintainer] for-X branch — your-handle`
2. Укажи time commitment (рекомендую: минимум один квартал = 3 месяца)
3. Кратко опиши свой бэкграунд в этой области

См. [`CONTRIBUTORS.md`](CONTRIBUTORS.md) за текущим списком мейнтейнеров.
